Shared props

The form input components (ShuoInputText, ShuoInputNumber, ShuoSelectMenu, ShuoDatepicker, ShuoCheckbox, ShuoCheckboxGroup, ShuoRadioGroup, ShuoSwitch, ShuoTextarea, ShuoFile, ShuoMonths, ShuoPhone) all support the props below, which are not repeated on each component page:

size
'xs' | 'sm' | 'md' | 'lg' | 'xl'
Component size; components of the same size have the same height. When not passed, it falls back to the size of UFormField, then the site-wide setting, and finally lg. See Size and UFormField.
disabled
boolean
Disables the component. When not set, it follows the disabled state of UForm.
loading
boolean
Shows a spinner and disables interaction.
skeleton
boolean
Covers the component with a skeleton and pauses interaction while keeping the layout. The bound value is kept when switching back, and form validation is not affected.
id
string
Input id; when not set, it follows UFormField. On ShuoMonths it points to the years input (the total months input in narrow containers), on ShuoPhone to the area code input; ShuoFile only follows UFormField.
name
string
Field name; when not set, it follows UFormField.

Except for ShuoDatepicker (which uses state instead; see Datepicker) and ShuoFile, components also support Nuxt UI's color (component color). Input-style components other than ShuoDatepicker and ShuoFile also support highlight (emphasized border); checkboxes and groups have no border and do not support highlight. The color and error border of ShuoFile follow UFormField.

With UForm and UFormField

Wrap the component in UFormField with name matching the schema field. The component picks up the id, size, disabled and error state of UFormField, and triggers validation on input, blur and change:

<!-- Name -->
<UFormField label="Name" name="name" required>
  <ShuoInputText v-model="state.name" />
</UFormField>

None of the components below pass size or disabled: the size comes from UFormField and the disabled state from UForm. Press "Submit" first to see the error borders and messages of empty fields; fill everything in and submit again to see a notification with the submitted data.

NTD
<template>
  <ExampleOptions>
    <ExampleOption v-model="fieldSize" label="UFormField size" :items="sizes" />
    <ExampleOption
      v-model="formDisabled"
      label="UForm disabled"
      :items="[false, true]"
    />
  </ExampleOptions>

  <UForm
    :schema="schema"
    :state="state"
    :disabled="formDisabled"
    class="flex flex-col gap-4"
    @submit="onSubmit"
  >
    <div class="grid gap-4 sm:grid-cols-2">
      <!-- Name -->
      <UFormField label="Name" name="name" :size="fieldSize" required>
        <ShuoInputText v-model="state.name" />
      </UFormField>

      <!-- Amount -->
      <UFormField label="Amount" name="amount" :size="fieldSize" required>
        <ShuoInputNumber v-model="state.amount" unit />
      </UFormField>

      <!-- Type -->
      <UFormField label="Type" name="type" :size="fieldSize" required>
        <ShuoSelectMenu v-model="state.type" :items="types" />
      </UFormField>

      <!-- Application date -->
      <UFormField
        label="Application date"
        name="date"
        :size="fieldSize"
        required
      >
        <ShuoDatepicker v-model="state.date" clearable />
      </UFormField>
    </div>
    <div class="flex gap-2">
      <UButton type="submit" label="Submit" />
      <UButton
        label="Clear"
        color="neutral"
        variant="soft"
        :disabled="formDisabled"
        @click="clear"
      />
    </div>
  </UForm>
</template>

<script setup lang="ts">
import * as v from 'valibot';

type Size = 'xs' | 'sm' | 'md' | 'lg' | 'xl';

const sizes: Size[] = ['xs', 'sm', 'md', 'lg', 'xl'];
// The components pass no size or disabled; UFormField and UForm decide them.
const fieldSize = ref<Size>('md');
const formDisabled = ref(false);

const types = ['Normal', 'Urgent'];
const schema = v.object({
  name: requiredText('Name'),
  amount: requiredNumber('Amount'),
  type: requiredText('Type'),
  date: requiredText('Application date')
});
const state = reactive({
  name: '',
  amount: null as number | null,
  type: '',
  date: ''
});
const toast = useToast();

// submit only fires after validation passes; press "Submit" first to see each field's error border.
const onSubmit = (event: { data: v.InferOutput<typeof schema> }) => {
  toast.add({
    title: 'Submitted',
    description: JSON.stringify(event.data),
    color: 'success'
  });
};
const clear = () => {
  Object.assign(state, { name: '', amount: null, type: '', date: '' });
};
</script>

Color and highlight

color changes the focus border and the selection color; highlight keeps the input border in that color without focus (not supported by checkboxes and groups). ShuoDatepicker has no color; it uses state for the validation result (false for error, true for success).

Built on Nuxt UI

Shuo components that wrap a Nuxt UI component inherit the props types of the underlying component, so Nuxt UI props that are not redeclared also get autocompletion and type checking. Event arguments are typed too. Slots are forwarded to the underlying component, and the same refs as the underlying component are exposed.

ComponentInherited propsAvailable slotsExposed refs
ShuoInputTextUInputleading, default, trailinginputRef
ShuoInputNumberUInputleading, default, trailinginputRef
ShuoTextareaUTextarealeading, default, trailingtextareaRef, autoResize
ShuoFileUInputleading, defaultinputRef
ShuoSelectMenuUSelectMenuAlltriggerRef, viewportRef
ShuoCheckboxUCheckboxappend (component's own)—
ShuoRadioGroupURadioGrouplegend, item-append (component's own)—
ShuoCheckboxGroupUCheckboxGrouplegend, item-append (component's own)—
ShuoSwitchUSwitchlabel—
  • Inherited props are only used for type inference; at runtime they are passed to the underlying component through $attrs.
  • Props the component handles itself are not inherited and do not show up in autocompletion, such as modelValue. Input-style components (ShuoInputText, ShuoInputNumber, ShuoTextarea, ShuoFile) show their own loading icon, always using Nuxt UI's appConfig.ui.icons.loading, so loadingIcon is excluded as well and has no effect. ShuoSelectMenu lets USelectMenu show the loading icon, so loadingIcon works as usual.
  • Events are forwarded to the underlying component through $attrs as usual, with types taken from the underlying component's emits; for example, the argument of @blur is a FocusEvent.
  • Checkboxes, switches and groups support descriptions (description; for groups, the item's description field or the field set by descriptionKey): without a description the height matches an input of the same size; with one, the item grows and the description wraps, while its first line still lines up with fields without a description. The label stays on one line and is truncated with a tooltip showing the full text.
  • Checkboxes and groups do not support Nuxt UI's variant (card, table), indicator or highlight: the border and padding of card and table make options taller; indicator moves the checkbox, while the loading spinner stays where the left checkbox is; highlight only changes the border color of card and table. Passing them is a type error and they are not applied at runtime.

Slots

Input-style components can use #leading and #trailing to put icons or buttons before and after the input; ShuoSelectMenu can use every slot of USelectMenu. Checkboxes and groups have their own #append and #item-append for content next to the option label.

            size="xs"
            color="neutral"
            variant="link"
            aria-label="Clear"
            @click="keyword = ''"
          />
        </template>
      </ShuoInputText>
    </UFormField>

    <!-- Number input -->
    <UFormField label="#leading (ShuoInputNumber, alongside the unit)">
      <ShuoInputNumber v-model="amount" unit>
        <template #leading>
          <UIcon name="i-lucide-banknote" class="text-dimmed size-5" />

Exposed refs

After getting the component with a template ref, use the refs in the table to work with the underlying native elements, for example to focus, select all or open the menu.

<template>
  <ExampleOptions>
    <ExampleAction
      label="Select text"
      icon="i-lucide-text-select"
      :action="selectText"
    />
    <ExampleAction
      label="Focus amount"
      icon="i-lucide-text-cursor-input"
      :action="() => numberField?.inputRef?.focus()"
    />
    <ExampleAction
      label="Open menu"
      icon="i-lucide-chevrons-up-down"
      :action="() => selectField?.triggerRef?.click()"
    />
    <ExampleAction
      label="Move cursor to end of note"
      icon="i-lucide-arrow-right-to-line"
      :action="moveToEnd"
    />
  </ExampleOptions>

  <div class="grid gap-4 sm:grid-cols-2">
    <!-- Text input -->
    <UFormField label="ShuoInputText (inputRef)">
      <ShuoInputText ref="textField" v-model="text" />
    </UFormField>

    <!-- Number input -->
    <UFormField label="ShuoInputNumber (inputRef)">
      <ShuoInputNumber ref="numberField" v-model="amount" unit />
    </UFormField>

    <!-- Select menu -->
    <UFormField label="ShuoSelectMenu (triggerRef)">
      <ShuoSelectMenu ref="selectField" v-model="type" :items="types" />
    </UFormField>

    <!-- Multi-line text -->
    <UFormField label="ShuoTextarea (textareaRef)">
      <ShuoTextarea ref="textareaField" v-model="note" :rows="1" />
    </UFormField>
  </div>
</template>

<script setup lang="ts">
const textField = useTemplateRef('textField');
const numberField = useTemplateRef('numberField');
const selectField = useTemplateRef('selectField');
const textareaField = useTemplateRef('textareaField');

const text = ref('Alex Wang');
const amount = ref<number | null>(1200);
const types = ['Normal', 'Urgent'];
const type = ref('Normal');
const note = ref('Note content');

const selectText = () => {
  textField.value?.inputRef?.focus();
  textField.value?.inputRef?.select();
};
const moveToEnd = () => {
  const textarea = textareaField.value?.textareaRef;
  textarea?.focus();
  textarea?.setSelectionRange(note.value.length, note.value.length);
};
</script>

Skeleton

The skeleton keeps the layout space of the original control, following size, width, textarea rows and the option group layout, with no fixed height of its own. While it is on, the component cannot be clicked or used with the keyboard, and tooltips and open menus close.

A common use is an edit page loading data from the back end, with one loading state controlling the skeleton of every field. Press "Reload data" to try it: the layout stays the same during the skeleton, and the data fills in when it arrives.

<template>
  <ExampleOptions>
    <ExampleAction
      label="Reload data"
      icon="i-lucide-refresh-cw"
      :action="reload"
    />
  </ExampleOptions>

  <div class="grid gap-4 sm:grid-cols-2">
    <!-- Applicant -->
    <UFormField label="Applicant">
      <ShuoInputText v-model="form.name" :skeleton="pending" />
    </UFormField>

    <!-- Type -->
    <UFormField label="Type">
      <ShuoSelectMenu v-model="form.type" :items="types" :skeleton="pending" />
    </UFormField>

    <!-- Description -->
    <UFormField label="Description" class="sm:col-span-2">
      <ShuoTextarea v-model="form.note" :rows="3" :skeleton="pending" />
    </UFormField>

    <!-- Notify by -->
    <UFormField label="Notify by">
      <ShuoCheckboxGroup
        v-model="form.notify"
        :items="notifyOptions"
        :skeleton="pending"
      />
    </UFormField>

    <!-- Public -->
    <UFormField label="Public">
      <ShuoSwitch
        v-model="form.public"
        label="Make this case public"
        :skeleton="pending"
      />
    </UFormField>

    <!-- Attachment -->
    <UFormField label="Attachment">
      <ShuoFile v-model="form.file" :skeleton="pending" />
    </UFormField>
  </div>
</template>

<script setup lang="ts">
const types = ['Normal', 'Urgent'];
const notifyOptions = ['SMS', 'Email', 'Phone'];
const form = reactive({
  name: 'Alex Wang',
  type: 'Normal',
  note: 'The skeleton keeps the height and width of each field, so the page does not jump when the data arrives.',
  notify: ['Email'],
  public: true,
  file: null as File | null
});

// Simulate fetching the data again: the skeleton covers the fields meanwhile, then the new values fill in.
const pending = ref(false);
const reload = async () => {
  pending.value = true;
  await new Promise((resolve) => setTimeout(resolve, 1500));
  Object.assign(form, {
    name: 'Mia Chen',
    type: 'Urgent',
    note: 'The data has been reloaded.',
    notify: ['SMS', 'Phone'],
    public: false
  });
  pending.value = false;
};
</script>

Compared with loading: loading keeps the current value and shows a spinner inside the field, suited to a field doing its own work (such as fetching select options); skeleton covers the whole field, suited to when the page data has not arrived yet and the current value means nothing.

Locales

Component texts (placeholders, accessible names, validation messages, date picker texts and so on) follow the Nuxt UI locale (<UApp :locale>), with Traditional Chinese and English built in; components already on screen update immediately when it changes. The default texts mentioned on these pages are the English ones. Text props passed explicitly (such as title or placeholder) are not affected by the locale. See Locales and messages for setup and overrides.

"Component language" in the palette menu at the top right of the docs site switches the language of the component examples on the page; by default it follows the docs language.

Empty values

When the parent binds null / undefined, the components below write back the agreed empty value; unexpected values such as wrong types are also cleared to the agreed empty value. This applies both on mount and when the parent fills values in later. When clearing an unexpected value, ShuoInputText, ShuoTextarea, ShuoInputNumber, ShuoRadioGroup, ShuoPhone and ShuoDatepicker log a console.warn ([ShuoComponentName] … cleared); ShuoSelectMenu and ShuoMonths only clear, without a warning.

ComponentEmpty value
ShuoInputText, ShuoTextarea, ShuoRadioGroup, ShuoPhone''
ShuoSelectMenuemptyValue (default ''); [] when multiple
ShuoInputNumber, ShuoMonthsnull
ShuoDatepicker'' for a single date, [] for a range

Press "Apply null from the back end" to simulate the back end returning null for every field: the bound values below change to each component's agreed empty value. ShuoCheckboxGroup does not write back and stays null.

Bound values: {"text":"Alex Wang","amount":1200,"type":"Normal","date":"2026/10/25","days":["Mon"]}

<template>
  <ExampleOptions>
    <ExampleAction
      label="Apply null from the back end"
      icon="i-lucide-circle-slash"
      :action="applyNull"
    />
    <ExampleAction label="Restore" icon="i-lucide-undo-2" :action="restore" />
  </ExampleOptions>

  <div class="grid gap-4 sm:grid-cols-2">
    <!-- Text input -->
    <UFormField label="ShuoInputText → ''">
      <ShuoInputText v-model="form.text" />
    </UFormField>

    <!-- Number input -->
    <UFormField label="ShuoInputNumber → null">
      <ShuoInputNumber v-model="form.amount" />
    </UFormField>

    <!-- Select menu -->
    <UFormField label="ShuoSelectMenu → ''">
      <ShuoSelectMenu v-model="form.type" :items="types" />
    </UFormField>

    <!-- Date picker -->
    <UFormField label="ShuoDatepicker → ''">
      <ShuoDatepicker v-model="form.date" />
    </UFormField>

    <!-- Checkbox group -->
    <UFormField label="ShuoCheckboxGroup (no write-back)">
      <ShuoCheckboxGroup v-model="form.days" :items="days" />
    </UFormField>
  </div>
  <!-- Shown as JSON so empty strings and null can be told apart -->
  <p class="text-muted text-sm">Bound values: {{ JSON.stringify(form) }}</p>

<script setup lang="ts">
const types = ['Normal', 'Urgent'];
const days = ['Mon', 'Wed', 'Fri'];
const initial = {
  text: 'Alex Wang',
  amount: 1200 as number | null,
  type: 'Normal',
  date: '2026/10/25',
  days: ['Mon']
};
const form = reactive({ ...initial, days: [...initial.days] });

// Simulate the back end returning null for every field: each component rewrites its bound value to its agreed empty value.
const applyNull = () => {
  const fromApi = {
    text: null,
    amount: null,
    type: null,
    date: null,
    days: null
  };
  Object.assign(form, fromApi);
};
const restore = () =>
  Object.assign(form, { ...initial, days: [...initial.days] });
</script>

These components do not write back the parent's value:

  • ShuoCheckboxGroup: null or a non-array value shows everything unchecked; checking an option writes back the full array. Clearing gives [].
  • ShuoCheckbox: shows unchecked when the bound value is not trueValue.
  • ShuoFile: null after clearing.
