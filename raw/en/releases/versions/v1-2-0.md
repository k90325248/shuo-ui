# v1.2.0

> Released on October 27, 2026

Adds `ShuoSwitch`, which can call an API after toggling, updating only on success and reverting on failure; tables and list cards support row selection; checkboxes, choice groups and switches support descriptions. Component changelogs on the docs site now follow the docs language. Before upgrading, read "Upgrade notes" below: choice groups whose item data already has a `description` field will show it after upgrading.

## ✨ Highlights

### 🔀 A switch that confirms the change before updating

The new `ShuoSwitch` keeps the props of `USwitch` and adds `action`: after toggling, it shows the new value, loading and disabled. If the action returns `false` or throws, the switch reverts; any other result updates `v-model` and emits `change`. Use it for settings saved through an API as soon as they change: [Switch](https://k90325248.github.io/shuo-ui/components/choice/switch)

```vue
<ShuoSwitch v-model="enabled" label="Enable account" :action="(value) => api.setEnabled(value)" />
```

Its height matches inputs of the same size, and a long label is truncated with a tooltip showing the full text, the same as the checkbox. `size`, `color` and `loadingIcon` can be set site-wide with `components.switch`. Buttons need no wrapper: `loading-auto` on `UButton` already provides the same loading state.

### ☑️ Row selection in tables and list cards

With `selectable`, `ShuoTable` and `ShuoListCard` add a selection column at the front, and the selection is bound to an array of keys with `v-model:selected`: [Selection in Table](https://k90325248.github.io/shuo-ui/components/layout/table#selection)

```vue
<ShuoListCard
  v-model:selected="selected"
  :data="rows"
  :columns="columns"
  selectable
  row-key="ID"
  :row-selectable="(row) => row.status !== 'Closed'"
  @page-change="search"
/>
```

- `row-key` is a field name or a function. With server-side pagination, selections on other pages are kept when changing pages, so rows selected across pages can be handled together.
- Select all in the header only selects the selectable rows on the current page and shows an indeterminate state when only some are selected; with `select-all` set to `false`, the header shows the `selection-header` text instead.
- Rows for which `row-selectable` returns `false` cannot be selected; all checkboxes are disabled while loading.
- `checkbox-props` sets the `class`, `ui`, `color`, `size` and icons of the checkboxes. Put `{ id: 'select' }` in `columns` to place the selection column, or replace it entirely with the `#select-header` and `#select-cell` slots.
- `selectAll` and `checkboxProps` can be set site-wide with `components.table`.

Without `selectable` nothing changes, and controlling selection yourself through `tableProps` still works.

### 📝 Descriptions on checkboxes, choice groups and switches

`ShuoCheckbox`, `ShuoRadioGroup`, `ShuoCheckboxGroup` and `ShuoSwitch` support descriptions (for groups, the item's `description` field or the field set by `description-key`). Without a description the height still matches inputs; with one the control grows and the description wraps, while the first line stays aligned with the fields next to it. In horizontal groups the whole row grows, and the description does not squeeze the labels of other items: [Checkbox description](https://k90325248.github.io/shuo-ui/components/choice/checkbox#description)

```vue
<ShuoCheckbox
  v-model="subscribe"
  label="Subscribe to the newsletter"
  description="A weekly email; unsubscribe at any time"
/>
```

## 🚀 New components

- **Switch:** Switch that can run an action after toggling, updating the bound value only on success and reverting on failure or errors ([docs](https://k90325248.github.io/shuo-ui/components/choice/switch))

## ⚠️ Upgrade notes

### The description field of items is shown

Radio and checkbox groups used to hide item descriptions, ignoring any `description` field in the item data. It is now shown below the item label and makes the item taller.

If your items come straight from back-end data that happens to have a `description` field (for example remarks in a code table), the page will show it after upgrading. To hide it, remove the field before passing the items:

```ts
const options = computed(() => codes.value.map(({ description: _description, ...item }) => item));
```

## 📖 Docs site

- **Releases:** A new Releases tab in the header shows the release notes of every version, the same as the GitHub Releases, in English on the English site.
- **Localized changelogs:** The changelog at the end of each component page now shows English or Chinese text by docs language, without `feat:` or `fix:` prefixes.
- **New pages:** A new [Switch](https://k90325248.github.io/shuo-ui/components/choice/switch) page; the Table, ListCard, Checkbox, RadioGroup and CheckboxGroup pages add usage and examples for selection and descriptions; the examples on the shared props page include the switch.

## 📦 Installation

```bash
pnpm add github:k90325248/shuo-ui#v1.2.0
pnpm add @iconify-json/lucide # recommended, icons are bundled
```

Enable the module in `nuxt.config.ts` and add `@import '@shuo/ui/css';` to your CSS; see [Installation](https://k90325248.github.io/shuo-ui/getting-started/overview/installation) on the docs site.
